2. Environment setup

1Create/activate the virtual environment
From your project folder in PowerShell: 
python -m venv venv
venv\Scripts\activate

If activation is blocked by execution policy, see the Troubleshooting section below.

2Install dependencies
venv\Scripts\python.exe -m pip install -r requirements.txt

Installs torch, torchvision, pycocotools, numpy, pandas, matplotlib, pillow, pyyaml. The torch download is large (100+ MB) — this can take a few minutes.

3Point VS Code at the same environment
Ctrl+Shift+P → "Python: Select Interpreter" → choose the venv\Scripts\python.exe inside your project folder — the same one you just installed packages into. (Or click the interpreter name in the bottom-right status bar for the same picker.)
Only use one venv per project. Having two different virtual environments (e.g. one in your project folder and one elsewhere) is a common source of confusing "module not found" errors — packages installed in one aren't visible from the other. Pick one, install everything there, and point both the terminal and VS Code's interpreter at it.

3. Common setup errors

PowerShell: "running scripts is disabled on this system"

PowerShell blocks .ps1 activation scripts by default. Fixes, easiest first:

# Run the activate script once, bypassing policy just for this command:
powershell -ExecutionPolicy Bypass -File venv\Scripts\Activate.ps1

# OR permanently allow local scripts for your user account:
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

# OR skip activation entirely — call the venv's python directly:
venv\Scripts\python.exe train.py --config data.yaml

ModuleNotFoundError: No module named 'numpy' (or torch, etc.)

This means whichever Python is currently running doesn't have the package installed — usually because VS Code's debugger is using a different interpreter than the one you ran pip install in. Check the interpreter shown in VS Code's bottom-right status bar, and either install into that same environment or switch the interpreter to match the one that has the packages:

venv\Scripts\python.exe -m pip install -r requirements.txt

FileNotFoundError: '...train.py' or '...\_annotations.coco.json'

Almost always a wrong working directory or wrong file name/location. Checklist:

# Make sure you're actually in the project folder:
cd /d D:\your-project-folder
dir

# Confirm the dataset files exist exactly where data.yaml says:
dir dataset\train
dir dataset\valid

Roboflow's COCO export usually names the annotation file exactly _annotations.coco.json (leading underscore). If yours is named differently, edit train_ann / val_ann in data.yaml to match.

argparse error: "the following arguments are required: --weights, --images"

This happens when running a script (like detect_weeds.py) via VS Code's Run/Debug button with no arguments configured. Either run it from the terminal with the flags directly, or add an "args" list to .vscode/launch.json.

4. Training

1Quick smoke test
venv\Scripts\python.exe train.py --config data.yaml --epochs 1

Confirms the dataset loads and one full train+val loop runs before committing to a long training session.

2Full training run
venv\Scripts\python.exe train.py --config data.yaml

Trains for the epoch count in data.yaml (default 50). Writes checkpoints\best.pth (best val loss), checkpoints\last.pth, checkpoints\resume_state.pth, and logs\metrics.json.

3Resume if interrupted
venv\Scripts\python.exe train.py --config data.yaml --resume checkpoints\resume_state.pth
Watch for overfitting on small datasets. If val_loss stops improving (or starts rising) while train_loss keeps dropping, the model is memorizing the training images rather than generalizing. This is expected with very few training images — always use checkpoints\best.pth (lowest val loss), not last.pth.

5. Evaluation

1Plot training curves
venv\Scripts\python.exe plot_training_curves.py --log logs\metrics.json --out results\training_curves.png
2Run detection on the test set
venv\Scripts\python.exe detect_weeds.py --weights checkpoints\best.pth --images dataset\test --export_coco

Saves annotated images (boxes + masks + labels) to results\inference_samples\, plus predictions.json for scoring.

3Compute mAP
venv\Scripts\python.exe compute_map.py --gt dataset\test\_annotations.coco.json --pred results\inference_samples\predictions.json
4Error analysis
venv\Scripts\python.exe error_analysis.py --gt dataset\test\_annotations.coco.json --pred results\inference_samples\predictions.json --images dataset\test

Produces a confusion matrix, an IoU histogram, a score histogram, and saved crops of the worst false positives/negatives.

6. Automatic detection (no commands needed)

For a "drop an image in, get a result out" workflow instead of running commands each time:

1Start the watcher once
Double-click run_auto_detect.bat (or run venv\Scripts\python.exe auto_detect.py). It loads the model once and then waits.
2Drop images into the watch folder
Copy any .jpg/.png into the folder set by WATCH_FOLDER in auto_detect.py (default dataset/test). Within a few seconds it's detected automatically and printed to the console.
3Check the results
Annotated copies appear automatically in results\auto_detect\. Leave the window running to keep detecting new images as they arrive; close it or press Ctrl+C to stop.
